# 面试讲解脚本

三个版本：30 秒电梯演讲、3 分钟标准讲解、8 分钟深度讲解。

---

## 30 秒电梯演讲

> BeautyGo 是一个上门美妆 O2O 平台的 AI 产品经理作品集。我用 Vibe Coding 模式，3 个里程碑从零做到可运行 MVP：客户能浏览化妆师、选套餐、预约；化妆师能提交入驻申请；运营能审核管理。项目约 2500 行代码，38 个 API 测试全通过，前后端都可演示。核心展示的是产品收束能力和 AI 协作研发流程。

## 3 分钟标准讲解

### 1. 项目定位（30 秒）

BeautyGo 是一个**求职面试向的 AI 产品经理作品集**。选择上门美妆 O2O 作为业务载体，因为它天然具备双边撮合、场景化服务、交易闭环等产品设计要素，足以展示完整的产品能力链路。

关键决策：**从商业化平台收束为作品集**。砍掉了真实支付、IM、地图、多城市运营，聚焦在"产品判断 → 需求收束 → PRD → 流程设计 → AI 协作研发 → MVP 验收"这条主线。

### 2. MVP 范围取舍（30 秒）

**做了什么：**
- 化妆师入驻申请 + 后台审核闭环（供给侧冷启动）
- 客户浏览化妆师、选套餐、模拟预约（需求侧验证）
- 运营后台看板（数据可视化）
- 作品集展示页（面试讲解入口）

**不做什么及原因：**
- 新娘全天跟妆：高复杂度，MVP 不验证
- 派单/抢单：先验证直约模式
- 内容社区：非交易闭环必需

原则：**先锁业务闭环，再扩功能广度**。每个里程碑都是一个可独立验收的垂直切片。

### 3. AI 协作方式（45 秒）

采用 **Vibe Coding** 模式：人类定义产品方向和业务规则，AI Agent 负责架构设计、代码实现和质量检查。

五个 Agent 角色：
1. **Delivery Lead** — 编排里程碑、风险、优先级
2. **Product Breakdown** — PRD 拆 epic / story / 验收标准
3. **Architecture** — 模块边界、数据模型、集成点
4. **Implementation** — 按切片写代码、跑测试
5. **QA & Release** — 回归、验收、go/no-go

协作原则：事件触发同步（不刷屏）、垂直切片交付、产品规则先收紧、决策可回溯。

### 4. 技术架构（30 秒）

pnpm monorepo，四层结构：
- **super-app**（Vue 3）— 客户 + 化妆师入口
- **admin-web**（Vue 3 + Router）— 运营审核后台
- **api**（NestJS）— 领域逻辑 + 集成层
- **domain-types** — 共享业务语言，PRD 术语 single source of truth

技术选型理由：NestJS 的 DI 和装饰器路由适合模块化 API；Vue 3 轻量适合 SPA；monorepo 让类型包跨前后端复用。

### 5. 当前成果（15 秒）

- ~2500 行核心代码，3 个里程碑完成
- 10 个 API 端点，38 个测试全通过
- 5 个前端页面，typecheck + build 全绿
- 可演示：客户预约流程、化妆师入驻、运营审核、后台看板

## 8 分钟深度讲解

在 3 分钟版本基础上，扩展以下部分：

### 产品决策详解（2 分钟）

**为什么选上门美妆？**
- 高频低客单 vs 低频高客单：上门美妆介于两者之间，适合 MVP 验证
- 双边撮合：天然需要供给侧（化妆师）和需求侧（客户）的产品设计
- 场景化：旅拍/聚会/面试/婚礼，每个场景对应不同的套餐设计和定价策略
- 非标服务：不像打车那样标准化，需要展示化妆师作品集、评价、擅长场景

**收束决策的过程：**
最初 PRD 按完整商业平台设计（支付、IM、地图、保险、多城市）。审视后发现：
1. 作品集的目标是展示产品能力，不是做一个能上线的商业产品
2. 真实支付/IM/地图需要企业资质和第三方接入，与作品集目标无关
3. 核心展示链路是：产品判断 → 需求收束 → PRD → 流程设计 → AI 协作 → MVP

所以砍掉所有需要外部资质的功能，聚焦在"产品能力可视化"。

### 技术细节（2 分钟）

**领域类型包的设计：**
`packages/domain-types` 是整个项目的关键设计决策。它定义了 Booking、ArtistApplication、ServicePackage、MarketplaceArtist 等核心业务类型，前后端共享。

好处：
- PRD 中的术语直接变成代码中的类型名
- 前后端接口契约自动对齐
- 重构时改一处全生效

**Mock 数据策略：**
MVP 阶段用内存 Map 存储，不接数据库。好处是：
- 零外部依赖，clone 即可运行
- 测试快，不需要 mock 数据库
- 演示时数据可控

**测试策略：**
用 Node.js 内置 test runner（`node:test`），不用 Jest。好处是零依赖、原生支持。38 个测试覆盖 store CRUD、controller 权限校验、输入验证。

### AI 协作深度（1 分钟）

**Vibe Coding 的核心理念：**
- 人类负责"做什么"和"为什么做"
- AI 负责"怎么做"和"做得对不对"
- 同步节奏：开始新切片、锁定决策、出现 blocker 时才同步

**实际协作模式：**
1. 人类写 PRD，AI 拆 epic/story
2. 人类审核架构方案，AI 实现代码
3. AI 跑测试和 typecheck，人类验收功能
4. 每个里程碑结束时，AI 写复盘文档

**可回溯性：**
所有决策记录在 `docs/` 目录，git 留痕。面试官可以追溯任何技术决策的上下文。

### 演示建议（1 分钟）

**推荐演示路径（5 分钟）：**
1. 打开 super-app，展示作品集概览页
2. 切换到客户角色，浏览化妆师、选套餐、提交预约
3. 切换到运营角色，查看审核台和后台看板
4. 打开 terminal，跑 `pnpm --filter @beautygo/api test`，展示 38 个测试全绿
5. 打开 VSCode，展示 domain-types 包的类型定义

**常见 Q&A：**

**Q: 为什么不用真实数据库？**
A: 作品集目标是展示产品能力，不是做一个可上线的系统。内存存储让项目零依赖、clone 即跑，面试官 30 秒内就能启动演示。

**Q: AI 写的代码质量怎么保证？**
A: 三层保障：typecheck 静态检查、38 个单元测试、每个里程碑人工验收功能。AI 写代码，人审产品。

**Q: 为什么不直接用现成的低代码平台？**
A: 作品集要展示的是"产品判断 + AI 协作 + 代码实现"的完整链路。低代码平台只能展示前两层，无法展示架构设计和技术选型能力。

**Q: 这个项目能商业化吗？**
A: 技术架构上可以（NestJS + Vue 3 是生产级技术栈），但需要补充：真实数据库、支付接入、实名认证、IM 通讯、地图服务、SMS 验证码。这些需要企业资质和第三方接入，不在作品集范围内。

**Q: 你的角色是什么？**
A: 产品经理 + AI 协作编排者。我定义产品方向、写 PRD、做范围取舍、审核架构方案、验收功能。AI Agent 负责代码实现和质量检查。
